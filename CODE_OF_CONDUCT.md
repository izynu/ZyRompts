# Code of Conduct

## The short version

Be accurate, be direct, be decent. Critique the work, not the person. Assume the
other person is trying to make the project better until they show otherwise.

## Expected behaviour

- **Give evidence, not emphasis.** "This will fail because the loop indexes one
  past the end, see line 42" is a contribution. "This is wrong" is not.
- **Accept correction plainly.** If you were wrong, say so and move on. No
  apology theatre, no defensiveness.
- **Disagree once, then commit.** State your position with support. If the
  maintainers decide otherwise, follow the decision unless it is unsafe.
- **Keep it short.** A long review that buries the one blocking issue wastes
  everyone's time.
- **Respect different experience levels.** A beginner's correct question is
  still correct.

## Unacceptable behaviour

- Harassment, insults, or personal attacks.
- Discriminatory language or imagery, including in issues, commits and reviews.
- Publishing someone's private information without consent.
- Deliberately wasting reviewers' time with bad-faith arguments.
- Posting real credentials, personal data, or confidential material in an issue,
  a commit or a pull request.
- Sustained disruption of discussion.

## Scope

This applies to issues, pull requests, reviews, commit messages, discussions and
any space where someone represents the project.

## Enforcement

Report a problem to the maintainers through the private contact in `SECURITY.md`
or by emailing a maintainer directly. Reports are handled confidentially.

Responses, proportional to the behaviour:

1. A private note explaining the problem and what to change.
2. A formal warning, with a stated consequence for repetition.
3. Temporary removal from participation.
4. Permanent removal, for a serious or repeated violation.

The maintainers will not act on a report without reading the context. A single
blunt technical disagreement is not harassment; a pattern of personal attacks
is.
