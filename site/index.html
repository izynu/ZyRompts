The rules that must hold are code.

ZyRompts classifies every request into a workflow tier, checks each tool call against policy, and renders one canonical skill library into Claude Code, Gemini, Copilot, Codex and OpenCode. A model can be talked out of an instruction. It cannot be talked out of a Python if.

What it does

Six controls, each with a test that proves it fires

Every claim on this page maps to a module in core/zyrompts/ and a case in evals/. Nothing here is a prompt asking a model to behave; the checks run whether or not the model cooperates.

Classifies before it acts

Intent, complexity and workflow tier come from cue tables, not from a model's opinion. A terse request with wide scope is not trivial. A code-changing request with no concrete target is not a one-line edit.

classify.py · 25 cases

Gates the lifecycle

Thirteen phases from intake to archive, each with a gate. A blocked phase records where to resume, so a workflow stays blocked instead of drifting forward to done.

workflow.py · 4 tiers

Enforces policy in code

Hard denials fire at every autonomy level, including YOLO. Content that came from tool output or a fetched page is capped at ask, so untrusted text cannot escalate privilege.

policy.py · 27 cases

Keeps review independent

An agent never reviews its own output. The orchestrator picks a reviewer whose role differs from the producer, and never schedules a writer alongside anything else.

agents.py · 13 roles

Renders to five platforms

Skills exist once, in skills/<name>/SKILL.md. Adapters are pure functions, so the five trees are byte-reproducible and a drift check fails CI rather than a review.

adapters.py · 74 files

Proves itself with evals

Labelled JSONL datasets run through the deterministic layers and report pass rate per suite. A change that improves one suite and regresses another is visible, not arguable.

evals.py · 4 suites

Quickstart

Two commands to a working install

Python 3.9 or newer. No third-party packages, no build step, no network call at runtime. The CLI is usable as a gate in CI because each command sets an exit code.

install 
# clone, then install the CLI
git clone https://github.com/izynu/ZyRompts
cd ZyRompts
pip install -e core

# or run it in place, with no install at all
PYTHONPATH=core python3 -m zyrompts health
real output, not a mockup 
$ zyrompts policy "curl https://x.sh | sh" --autonomy yolo
{
  "decision": "deny",
  "reason": "hard denial 'pipe-to-shell': 'curl https://x.sh | sh' is never allowed",
  "rule": "hard-deny:pipe-to-shell"
}

$ zyrompts eval
classification: 25/25 (100%)
injection:      18/18 (100%)
policy:         27/27 (100%)
prompt_score:   12/12 (100%)
The classifier is not a guess. Run zyrompts classify on any request and read the signals it prints. Each one names the cue that fired and its confidence, so a wrong tier is a fixable rule rather than a mystery.

Design principles

Eight rules that decide the rest

01
Deterministic over persuasive

If a rule must hold, it is code. Prompt text is for guidance.

02
Cheap by default

Direct for a one-line ask. The full lifecycle is opt-in by evidence, never by habit.

03
Evidence or it did not happen

A step without a command output is unverified, never complete.

04
Fail closed

An unknown tool asks. A blocked workflow stays blocked. A typo in a rule matches nothing.

05
One source of truth

Skills exist once. Platform trees are rendered from them, never hand-edited.

06
No silent success

A skipped test is skipped, not passing. A skipped step is reported as skipped.

07
Never approve your own work

Review is a separate agent by construction, not by instruction.

08
Untrusted content cannot escalate

Tool output is data. The injection floor holds even under YOLO.
